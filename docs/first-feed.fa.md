# از فید آزمایشی تا یک ردیف در StarRocks

این تحویل مسیر تشخیص را روی CPU و با مدل آمادهٔ YuNet اجرا می‌کند. کاربر روی کادر یک فریم کلیک می‌کند و crop، پیام Kafka و ردیف SQL همان مشاهده را می‌بیند. برای اجرای محلی Linux x86-64 با Docker Compose v2، Python 3.10+، FFmpeg و ffprobe لازم است. ساخت نخست به اینترنت برای imageها، Maven، عکس نمونه و مدل نیاز دارد.

## اجرای آزمون

از ریشهٔ ریپو اجرا کنید. پورت‌های میزبان 19000، 19030 و 19092 باید آزاد باشند. برای آغاز FE، بعد از دریافت و بازکردن imageها بیش از ۵ گیگابایت فضای آزاد در محل metadata لازم است. سرویس‌ها فقط روی loopback منتشر می‌شوند. این تنظیمات تک‌گره‌ای برای آزمایش محلی‌اند.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r tools/requirements-review.txt
python tools/fixture.py
docker compose up -d kafka s3 starrocks
docker compose build detector
python tools/acceptance.py --speed 1
```

آزمون برای آماده‌شدن backend، ساخت جدول، topic و bucket صبر می‌کند. عبارت PASS و مسیر گزارش خصوصی در پایان چاپ می‌شوند. برای توقف سرویس‌ها و حفظ داده‌ها از `docker compose stop` استفاده کنید.

## فید و سرعت پخش

فایل `private/feed.mkv` بیست فریم ۵۱۲×۵۱۲ با نرخ ۱۰fps دارد. ده فریم اول یک تصویر نمونه و ده فریم آخر زمینهٔ خالی‌اند. شبیه‌ساز فایل را با FFmpeg به ترتیب نمایش decode می‌کند. فاصلهٔ زمانی فریم‌ها از PTS و time base فایل گرفته و بر ضریب سرعت تقسیم می‌شود. مقدار ۱ یعنی زمان اصلی، ۰٫۵ یعنی نیم‌سرعت و ۲ یعنی دوبرابر. اگر مصرف‌کننده عقب بماند، فریم‌های بعدی با تأخیر تحویل می‌شوند. شمار فریم‌های decodeشده و زمان واقعی پخش در stdout دیده می‌شود.

هر اجرای آزمون یک source_id تازه دارد و در همان اجرا فریم شمارهٔ ۵ دو بار با همان source_id پردازش می‌شود. برای تمرین مستقل پس از راه‌اندازی اولیه، دو بار دستور یکسان زیر را اجرا کنید و شناسه و offset را مقایسه کنید. آرگومان سوم شمارهٔ فریم از صفر است. انتخاب فریم ۱۵ سند فریم خالی تولید می‌کند.

```sh
docker compose run --rm detector /input/feed.mkv practice-camera 5 0.5
```

برای کلیپ خودتان، فایل را با نام جداگانه در `private/` بگذارید، آرگومان اول را به مسیر متناظر در `/input/` تغییر دهید و شمارهٔ فریم موردنظر را انتخاب کنید.

در این تحویل فقط فریم انتخابی وارد inference می‌شود. تعداد فریم‌های decodeشده، نرخ inference روی همهٔ فریم‌ها را نشان نمی‌دهد. فایل‌های کوتاه، seekable، با ابعاد ثابت و جهت نمایش عادی برای این شبیه‌ساز در نظر گرفته شده‌اند. مسیر RTSP باید با مدیریت قطع اتصال و سیاست صف جداگانه سنجیده شود.

## آزمون و مشاهدهٔ خروجی

۱. آزمون، شماره و PTS فریم را با ffprobe و مقدار هش فایل مقایسه می‌کند. برای فریم منتخب دقیقاً یک چهره انتظار می‌رود. YuNet روی CPU با ONNX Runtime اجرا می‌شود. ورودی ۶۴۰×۶۴۰ با حفظ نسبت و padding، ترتیب BGR، حد امتیاز ۰٫۸۵ و NMS با IoU برابر ۰٫۳ است.

۲. رویداد تشخیص روی `face.detected.v1` با کلید `detection_id` منتشر می‌شود. آزمون پیام را از همان partition و offset می‌خواند و تک‌تک فیلدها را با ردیف StarRocks مقایسه می‌کند. PNG برگشتی از S3 باید هم هش درست داشته باشد و هم پیکسل‌هایش دقیقاً با برش کادر از فریم برابر باشد.

۳. موتور تشخیص، پیش از انتشار، سند فریم را در S3 با ایجاد شرطی ثبت می‌کند. کلید آن شامل منبع، هش فایل، نسخهٔ detector، track و شمارهٔ فریم است. سند، payload نهایی و شناسه‌ها را نگه می‌دارد. اجرای دوبارهٔ worker با همان ورودی payload قبلی را منتشر می‌کند. کادرها به شکل x، y، عرض، ارتفاع و مبدأ بالا-چپ هستند. مختصات پنج نقطهٔ صورت نیز در فریم اصلی‌اند. شناسه فقط یک مشاهده در یک فریم را مشخص می‌کند.

۴. آزمون تا عبور Routine Load از offset بازپخش صبر می‌کند و برای منبع اجرا یک ردیف با محتوای یکسان می‌خواهد. گزارش، زمان ورود فریم تا نخستین مشاهدهٔ SQL را ثبت می‌کند. این اندازه‌گیری تک‌نمونه است. برای تخمین p95، دقت، نرخ پردازش پایدار و ظرفیت چندجریانی به اجراهای بعدی نیاز است.

۵. اگر Jupyter دارید، دفتر زیر را در محیط خود باز کنید. برای نصب اختیاری در همین محیط مجازی، از `python -m pip install jupyterlab` استفاده کنید. هر سلول را اجرا کنید و روی کادر چهره کلیک کنید تا crop، offsetها و ردیف SQL باز شوند.

```sh
cp notebooks/review.ipynb private/review.ipynb
jupyter lab private/review.ipynb
```

## محدودهٔ داده و مراحل بعد

داده‌های واقعی در `private/` و volumeهای محلی هستند. ریپو فقط دستور ساخت، کد، notebook بدون خروجی و مدرک عددی دارد. عکس نمونهٔ astronaut از مجموعهٔ scikit-image و مدل از OpenCV Zoo هنگام آماده‌سازی با SHA-256 بررسی می‌شوند. اگر سیستم پیش از ثبت سند فریم متوقف شود ممکن است crop بدون ارجاع در bucket بماند. انتشار بعد از ثبت سند انجام می‌شود؛ پاک‌سازی دوره‌ای اشیای بدون ارجاع برای عملیات طولانی‌مدت لازم است. [عکس نمونه](https://scikit-image.org/docs/stable/api/skimage.data.html#skimage.data.astronaut) · [مدل YuNet](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet)

پس از بازبینی این تحویل، گالری نسخه‌دار و شناسایی با SFace اضافه می‌شوند. سپس روی GPU مقصد، آزمون ۱، ۲، ۴ و ۸ جریان با همان ورودی ثابت انجام می‌شود. برای هر تغییر، انتظار قبل از اجرا و اندازه‌گیری واقعی پس از اجرا ثبت می‌شود.

## مبنای اندازه‌گیری تحویل اول

کلیپ ساخته‌شده در دو بار تولید، SHA-256 یکسان `51238b372406713fbe4ab379b60afbd084e158deb88942b64c097d82dbfb9e9e` داشت. جدول از دو اجرای واقعی CPU با منبع مستقل گرفته شده است. ساعت ورود فریم پیش از inference ثبت می‌شود و کلاینت SQL تقریباً هر ۱۰۰ میلی‌ثانیه نتیجه را می‌خواند.

| سرعت درخواستی | تعداد فریم decodeشده در هر پخش | زمان پخش از شروع ساعت فید تا پایان | تأخیر مشاهدهٔ اولین ردیف | offset نخست و بازپخش | ردیف نهایی برای منبع |
|---|---|---|---|---|---|
| ۱ برابر | ۲۰ از ۲۰ | ۱٫۹۰ ثانیه | ۲٫۸۶۲ ثانیه | ۱ و ۲ | ۱ |
| نیم‌سرعت | ۲۰ از ۲۰ | ۳٫۸۰ ثانیه | ۴٫۳۷۴ ثانیه | ۳ و ۴ | ۱ |

فریم ۵ در PTS برابر با ۵۰۰ و time base برابر با ۱/۱۰۰۰ است. در هر دو اجرا IoU با کادر دستی ۰٫۸۳۶ بود، پیکسل‌های crop برابر بودند و یک worker تازه همان کلید و بایت‌های پیام قبلی را منتشر کرد. برای فریم ۱۵ در سرعت دوبرابر، یک سند تهی در S3 و صفر ردیف تشخیص در SQL تأیید شد. سلول‌های دفتر بازبینی با گزارش واقعی اجرا شدند و کلیک روی کادر، crop و ردیف SQL را باز کرد.

محیط آزمون Linux x86-64 با Docker روت‌لس، Kafka 3.9.1، ذخیره‌ساز سازگار با S3 و StarRocks 3.4.10 بود. در این محیط، درایور VFS کپی لایه‌های image را روی دیسک ۳۲ گیگابایتی جا نمی‌داد. فایل‌های همان image رسمی StarRocks در حافظه باز شدند و FE و BE با heap کوچک‌تر FE و سقف فایل‌های باز متناسب با محیط اجرا شدند. image موتور تشخیص از Dockerfile پروژه با تنظیمات پراکسی و گواهی مختص محیط ساخته شد. اجرای پیش‌فرض Compose روی میزبان مقصد و محک GPU جداگانه باقی است.
